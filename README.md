# Bonny AntiDPI

Собственный ранний прототип обхода DPI для Windows 10/11 x64. Здесь есть свой обработчик TCP-пакетов и свой разбор TLS ClientHello. Windows 7 и macOS этой сборкой не поддерживаются.

## Что делает текущий прототип

- Перехватывает только исходящие TCP-пакеты на порт 443.
- Накапливает начало TLS ClientHello и читает SNI.
- Меняет границу TCP-сегмента перед именем целевого домена из `src/Bonny.Dpi/domains.txt`.
- Для остальных доменов и неподдерживаемых пакетов возвращает исходные пакеты без изменений.
- Ограничивает таблицу потоков 1024 записями; при достижении лимита новые потоки идут без изменений.
- Не сохраняет содержимое трафика на диск.
- Сразу передаёт неподдерживаемые и уже обработанные пакеты из общего буфера; копирует только данные ClientHello, которые нужно временно буферизовать.

Это первая стратегия для проверки; её успешность зависит от поведения DPI и сети. Исходящий TCP/443 остаётся в области перехвата до распознавания ClientHello. DPI-движок не обрабатывает QUIC/UDP, голос Discord, UDP-игры Roblox, ECH и IPv6 с заголовками Routing, Fragment, AH/ESP или опцией Home Address. IPv6 Hop-by-Hop и Destination Options поддерживаются. ClientHello в нескольких последовательных TLS records разбирается. Чтобы передавать UDP/QUIC через зашифрованный маршрут, подключи полный WireGuard-профиль Германии; это работает для всего IP-трафика, который Windows направляет в туннель.

Bonny не может увеличить скорость тарифа, Wi-Fi или сервера. Оптимизация уменьшает лишние копирования пакетов и нагрузку на сборщик мусора; выигрыш зависит от компьютера, сети и конкретного трафика и не гарантирует увеличение пропускной способности.

## Что можно ожидать от сервисов

| Сервис | Что может затронуть Bonny | Что пока не поддерживается |
| --- | --- | --- |
| Discord | HTTPS API, веб-клиент и CDN по TCP для discord.com, discordapp.com, discordapp.net и discord.media | Голос использует UDP; его может направить полный WireGuard-туннель |
| Telegram | HTTPS-сайты и API, если соединение использует TLS с видимым SNI | Некоторые протоколы приложения не обрабатываются DPI; WireGuard передаёт IP-трафик в туннель |
| YouTube | HTTPS по TCP, включая домены из списка | HTTP/3/QUIC использует UDP; его может направить полный WireGuard-туннель |
| Roblox | Сайт, вход и ресурсы по HTTPS/TCP | Игровые UDP-соединения могут идти через WireGuard |
| TikTok | HTTPS по TCP для доменов из списка | HTTP/3/QUIC использует UDP; его может направить полный WireGuard-туннель |
| SoundCloud | HTTPS по TCP для soundcloud.com и sndcdn.com | QUIC/UDP не обрабатывается DPI-модулем |
| Spotify | HTTPS по TCP для доменов Spotify и перечисленных CDN | Не гарантирует работу каждого типа аудиопотока; QUIC/UDP не обрабатывается DPI-модулем |

## Архитектура и границы поддержки

- `src/Bonny.Dpi/domains.txt` — общий список доменов для обработки; политика совпадает с доменом и его поддоменами, а не с именем процесса приложения.
- DPI-движок рассматривает исходящие TCP/443-соединения и может обработать только ClientHello с видимым SNI. ECH, QUIC/UDP, голос Discord и игровые UDP-соединения Roblox этим движком не обрабатываются.
- Отдельный полнотуннельный WireGuard-маршрут может передавать через пользовательский VPS IP-трафик, который Windows направляет в туннель, включая UDP/QUIC. Он не гарантирует соединение в сети со строгим белым списком: сеть может блокировать сам VPN-протокол или адрес сервера. Автономного режима «всегда работает» нет.
- Диагностика проверяет базовые DNS, TCP/443 и TLS-соединения до доменов сервисов. Успешная проверка не доказывает, что приложение целиком работает или что DPI обойдён.

Ни доменный список, ни одна стратегия не обеспечивают полный обход всех белых списков. Список ресурсов не является реестром приложений: у сервисов меняются CDN, адреса и протоколы, а один CDN может обслуживать разные сайты. Для новых доменов нужны подтверждённые источники и проверка, чтобы не добавлять широкие общие CDN-зоны. Проверка полного сценария требует тестирования в конкретной сети.

## Сборка и запуск из CMD

1. Установи .NET 10 SDK.
2. Запусти `Build-Bonny.cmd`.
3. Запусти `Run-Bonny.cmd`: если консоль ещё не запущена с правами администратора, Windows покажет запрос UAC. После подтверждения Bonny проверит или автоматически установит компоненты и запустит обработчик. В меню CMD пункт «Запустить обход» также сам запросит права при необходимости. При запуске GUI через `Run-Bonny-Dpi.cmd` кнопка «Запустить обход» использует ту же проверенную CMD-установку WinDivert.
4. Нажми Ctrl+C в консольном окне или выбери «Остановить Bonny» в меню значка в системном трее. Через значок можно скрыть окно CMD, пока Bonny работает, и вернуть его обратно; работа Bonny остаётся обозначена видимым значком.

Автоустановка скачивает официальный архив WinDivert 2.2.2-A, сверяет SHA-256 архива и обоих файлов, а затем кладёт x64 файлы рядом с Bonny. Сам драйвер запускается системой при старте обработчика с правами администратора. Если защитная программа блокирует загрузку, установка прекращается и не меняет настройки защиты Windows. Также доступны команды `Run-Bonny.cmd menu`, `Run-Bonny.cmd start`, `Run-Bonny.cmd setup`, `Run-Bonny.cmd check`, `Run-Bonny.cmd diagnose`, `Run-Bonny.cmd germany` и `Run-Bonny.cmd help`. В CMD-меню пункт 6 открывает импорт профилей и управление WireGuard-туннелем. Настройка VPS описана в [Germany/README.md](Germany/README.md). Графический вариант DPI остаётся доступен через `Run-Bonny-Dpi.cmd`: кнопка диагностики проверяет сеть, а кнопка WireGuard открывает CMD-меню профилей. Диагностический помощник предыдущего прототипа запускается через `Run-Bonny-Connection.cmd`.

В CMD-меню пункт 7 проверяет DNS, TCP/443 и TLS для Discord, Telegram, YouTube, Roblox, TikTok, SoundCloud и Spotify. Проверка использует текущие системные маршруты и показывает доступность базового HTTPS; она не проверяет голос, игровой UDP, аудиопотоки Spotify или успешность обхода DPI. Пункт 9 (`Run-Bonny.cmd update-media-sites`) загружает из указанного ниже раздела Википедии только сайты из столбца «Сайт» и обновляет отдельную помеченную секцию в `domains.txt`, сохраняя пользовательский список. Обновление выполняется вручную; Bonny не загружает список в фоне.

Список СМИ взят из [русскоязычной статьи Википедии](https://ru.wikipedia.org/wiki/Список_заблокированных_в_России_СМИ), раздел «Список заблокированных сайтов средств массовой информации». Это не официальный реестр РКН и не полный перечень блокировок: сведения могут быть неполными, устаревшими или ошибочными. [Единый реестр РКН](https://eais.rkn.gov.ru/) предназначен для проверки отдельных ресурсов и не предоставляет Bonny подтверждённый универсальный список всех заблокированных приложений. Bonny не выдаёт сторонний список за официальный и не обновляет его в фоне.

Для рекламы в Firefox выбери пункт 8 в `Run-Bonny.cmd` или выполни `Run-Bonny.cmd adblock`: Bonny откроет официальную страницу [uBlock Origin в каталоге дополнений Mozilla](https://addons.mozilla.org/firefox/addon/ublock-origin/). Установи расширение в Firefox; фильтрация сайтов выполняется самим расширением, а не DPI-модулем Bonny. Это не меняет сетевые настройки Windows.

После остановки Bonny закрывает свой перехватывающий handle. Windows может оставить службу драйвера WinDivert загруженной до перезагрузки; без открытого handle Bonny она не перехватывает пакеты. Не удаляй службу вручную, если WinDivert используют другие программы.

Для локальной проверки логики разбора и разделения TCP-пакета выполни:

```powershell
dotnet run --project .\src\Bonny.Dpi.Specs\Bonny.Dpi.Specs.csproj --configuration Release
```

Проверки включают ClientHello, созданный системным TLS-стеком Windows, разбор фрагментов в нескольких TLS records, домены семи настроенных сервисов, разделение буферизованного TCP-потока перед SNI, безопасный разбор IPv6 extension headers и контроль checksum IPv4/IPv6. Они работают без WinDivert и не подтверждают, что метод проходит DPI у конкретного провайдера.

WinDivert не включён в проект. При обычном запуске Bonny проверяет файлы и при необходимости скачивает официальный архив 2.2.2-A, сверяет контрольные суммы и устанавливает два x64-файла. Если Defender или другая защитная программа блокирует загрузку, установка останавливается; не отключай защиту ради запуска.

## Структура

- `src/Bonny.Dpi/Dpi/TlsClientHelloParser.cs` — разбор TLS ClientHello и SNI.
- `src/Bonny.Dpi/Dpi/TcpPacket.cs` — разбор IPv4/IPv6 TCP-пакетов, разделение payload и пересчёт checksum.
- `src/Bonny.Dpi/Dpi/WinDivertDpiEngine.cs` — ограниченный перехват, буферизация ClientHello и пропуск остальных пакетов.
- `src/Bonny.Dpi/domains.txt` — список доменов для обработки.

## DPI и немецкий WireGuard-туннель

Режим DPI меняет сегментацию выбранных TLS-запросов на этом компьютере, сам по себе он не шифрует трафик и не меняет внешний IP. Отдельный необязательный WireGuard-режим может направить IPv4-, IPv6- и UDP/QUIC-трафик через собственный VPS в Германии. Меню позволяет импортировать несколько профилей, выбрать один и вручную подключить, переподключить или отключить его. Одновременно Bonny разрешает только один работающий профиль. Для туннеля нужны VPS с публичными IPv4 и IPv6 и установленный на Windows официальный WireGuard-клиент. Пока VPS не создан и профиль не импортирован, немецкий IP не активен. Кнопка WireGuard в GUI открывает это же меню CMD.

`Bonny-Connection.ps1` остаётся отдельным диагностическим помощником из предыдущего прототипа.
